# Havoc Game Notes Hub

A single-file broadcast & media toolkit for the Huntsville Havoc (SPHL). No build, no server — one HTML file that runs in any browser.

## What's inside
- **Game packet generator** — pro media-notes standard: cover (news w/ auto-draft, standings, 4-column leaders, media contact), Meet the Team, Hockey Operations, Elite Prospects career-stat pages, scouting report (series history + league-ranked Match Up), quick facts, season splits + "last time it happened", game-by-game log, roster + pronunciation guide, franchise records, blank scoring worksheets, and the dense game sheet — with a section picker and Full/Booth presets. Derived pages compute from the per-game log (auto-filled from results + attendance; shots/PP/fights hand-entered on the Schedule tab)
- **Game sheet, lineup chart & line card** — printable, per-team colors, all 12 team logos embedded
- **Print Center** — one sticky toolbar (sub-view · page count · Refresh · Clear text edits · Print/Save PDF · Print everything for tonight), and a per-section **A− / pt / A+ / B / reset** control that moves the printed body size exactly 1 pt per click, bolds a section's body text, saves with your layout, and warns when a section stops fitting instead of clipping silently. Any page that would spill in the PDF is outlined in the preview and labelled with what's wrong — taller than one sheet, or running past the right edge — with a **reduce this section by 1 pt** button on the page itself; **Fit every page** steps every offender down until the whole document fits, and reports what it changed
- **The packet lays itself out** — player entries and every other block flow onto as few sheets as they fit on, two or three to a page, and a block never splits across a break: it moves whole. One printed `.page` is exactly one sheet, so the PDF can never paginate differently from the preview. A section that is within 10% of fitting on one fewer page drops a point automatically (floor 7 pt) and says so. Stat rows the club could not source collapse into a single "stat line not publicly available" note instead of a full-height row each, and league names print abbreviated. On the same content this took the full packet from 38 preview / 40 printed pages to 27 and 27
- **Page inspector** — alongside the page count, any page that overflows is outlined in red and any page under 40% full while blocks are still queued is outlined in amber, each with a one-click fix on the page itself
- **Per-block nudge controls** — every block on every printable page carries **A− / pt / A+ / B / ↑ / ↓ / ⏎ / 👁 / ⟲** on hover, and the same controls sit in a list of the whole packet under the section bar: size and weight per block, move a block earlier or later, force a page break before it, hide it from print without losing its data, or reset it. Settings save per block and per preset, survive reloads and games, and the page count updates as you go. **Settings → Reset all layout** puts everything back. None of it prints
- **Three presets** — Full, Booth and **Compact** (everything, at the tightest rhythm that still reads at 8 pt). Each preset remembers its own per-block layout
- **2026-27 schedule** — official 60-game slate + preseason, promo nights, results entry, season calendar (home red / away gray)
- **Standings & league reference** — 2026-27 rule changes, schedule matrix, all-time Havoc leaders, head-to-head, plus a seeded **2026 season review & New Teams 2026-27** card: the President's Cup final and full playoff bracket, the 12-team table (2025-26 records, finishes, 2026-27 head coaches) and FPHL franchise files for Athens and Pee Dee. Every block is editable in place with a one-click restore, and a red • marks anything still unverified. The venue reference covers all 12 buildings
- **Franchise files** — a deep, researched file on each of the 12 clubs: founding and arena, season-by-season table, all-time record, championships and Finals, all-time leaders, records and awards, attendance, retired numbers and the current coach, plus a **running "Havoc all-time vs. them"** line that starts from the published baseline and accumulates from your own game log, and a per-team storylines box pre-filled with cross-team notes. Every section is editable with a restore, sourcing caveats travel with the text (a red • flags computed, single-sourced or disputed numbers), and nothing here is ever overwritten by a sync
- **Live scorebar** — league-wide SPHL scores (recent finals, tonight, week ahead) that update every minute while games are on, every 15 minutes otherwise, and pause while the tab is hidden; standings and stats also quietly refresh hourly. It always resolves: connected with a timestamp, or failed with the reason, a Retry and the last cached scores. A compact tonight-only strip also sits on This Game
- **One explicit season** — a season picker sits at the top of Live Data, listing the league's real season names newest-first, and the active season prints beside the Refresh button in large type. The default is the highest season id that is neither a playoff nor a career aggregate — sorted numerically, never by array position and never from a "current" flag, which is what once had a Game Day Refresh pulling 2015 Playoffs. That one value drives every call: standings, skater and goalie stats, schedule, every team roster, career stats, headshots, the scoreboard and Elite Prospects linking, with each step in the run report naming the season it used. A season whose end date is more than 18 months past refuses to sync and says so
- **Preseason fallback, always labelled** — 2026-27 exists but the league hasn't published rosters or stats for it, so when a feed comes back empty the hub re-runs the same pull against the previous regular season and marks it: "2025-26 (last season) — 2026-27 not yet published". The label shows on screen and on every printed page. Nothing from another season is ever shown as if it were current, and the fallback stops firing by itself the day the league publishes
- **One Game Day Refresh** — a single button runs everything tonight needs in order (connect, standings, stats, schedule, rosters, career stats + headshots, EP links, scoreboard) with a step list showing each result; individual pulls live behind an Advanced disclosure, and the connection check runs itself and reports as a chip
- **Freshness everywhere** — every feed carries its own "Updated 6:42 PM", and every printed page ends with a single stacked footer block — the embargo stripe, then the freshness line, then the rule and the footer row, each on its own row so they cannot print on top of one another, with the flow above reserving its height — reading "Data: SPHL feed <date/time> · daily report <date> · printed <date/time>", plus "(includes manual edits)" when overrides are live
- **Booth display** — dark mode (following the OS by default) and a booth type scale, neither of which touches printed output
- **Keyless daily-report baseline** — a nightly GitHub Action (`.github/workflows/sphl-daily.yml`) fetches the league's public daily report (no key needed), parses it with `js/daily-report-parser.js`, and commits `data/sphl-daily.json`; the site loads it as its data floor with a source badge. The same parser powers manual import: open the report, save the page, upload the .html (or paste it) — per-section parse summary included, works offline. Live feed data overlays this when available
- **Live SPHL data** — one-tap sync from the league's HockeyTech feed (standings, all player/goalie stats, full schedule + auto-filled final scores, and every team's roster). Works both hosted (GitHub Pages etc.) and opened as a local file; the feed key is auto-detected, and everything is saved to this browser after each sync. The latest daily report can also always be pasted in by hand as a manual fallback — same parsed data either way
- **Player photos from the roster feed** — the league's roster response carries `player_image` and the hub uses it verbatim, keyed by the roster `id`. It tries the one larger size that exists (240x240, probe-confirmed; 240x320 and 360x480 return 404) and falls back to the feed's own 120x160. The 2026-27 Havoc roster is coaches-only so far, so every sync also backfills photos for returning players from 2025-26 by name; new signings stay text-only and pick up a photo automatically once the league publishes them. The service worker caches the CDN so packets still build with photos offline
- **The league feed owns the vitals** — hometown, height, weight, date of birth, age, position, jersey number, headshot and pronunciation come from the SPHL roster feed and overwrite whatever the club's bios file said, silently, on every sync. `homeplace` is the hometown (the feed's `hometown` field comes back empty); a birthplace prints separately only when it differs. A value you typed into the player editor yourself is the one thing the feed will not overwrite. Nothing is invented: the feed carries no handedness, no draft status and no phonetic spellings today, so those still come from the club's file, and every player the feed leaves without a pronunciation is listed on the Rosters tab as one to chase. A column that reads identically for every player on the roster — the rookie flag does — is treated as formatting, not fact, and ignored. 2026-27 has no players published yet, so returning players fill in from 2025-26 and re-sync when the league posts them
- **Signed-sheet roster with feed reconcile** — the club's own 2026-27 signed-players sheet is the roster's source of truth in preseason. Jersey numbers from the sheet outrank the league feed; when the feed disagrees, both numbers show with a one-click resolve. Players the feed adds are flagged for confirmation, players on the sheet are never dropped by a sync, and anyone left over from a prior season is parked as "unconfirmed" — visible for review, out of the packet — instead of deleted. A status panel on the Rosters tab reports which signings the league feed has published yet
- **Club bios import** — the media team's bios JSON (long media bio, vitals, awards, pronunciations, broadcast notes, college/pro stat tables) imports on the Rosters tab, matched to the roster by name, applying the club's spelling and using a quoted nickname as the on-air name. Unverified values are never written as fact: an unconfirmed pronunciation prints as "— ask him —", an unresolved identity is flagged rather than filled from a guess, and every open question from the file is listed in a panel to chase with the club. Career pages print the club's tables until the league feed has 2026-27 numbers. Meet the Team prints the written bio as prose under each player, then awards, then college and professional tables kept separate — goalies get goalie columns (record, GAA, SV%, SO, saves) and a playoff table of their own where the club supplied one — with league names abbreviated so the tables stay inside the sheet. Anything the file marked uncertain (a weight, a hometown, a date of birth, a spelling) prints as a small italic note beside the player, never as a stated fact
- **Embargo mode** — imported players are flagged **unannounced**: the app shows an embargo banner, internal prep copies carry a warning stripe, and a **Copy: internal prep / for distribution** switch in Print Center leaves those players out of anything meant to be handed round, noting how many were withheld. Clearing the flag in Settings puts them back everywhere. Imported bios live in the browser only and are git-ignored: this repository is public and serves the site, so unannounced material never goes into it
- **Mobile** — `mobile.css` (loaded after the inline styles) gives phones a compact header, a scrolling tab strip with an edge fade, one-row sub-view pills, a 2-up action grid, thumb-sized controls, 16px inputs so iOS never zooms on focus, wide tables that scroll inside their own box with a frozen first column, and a print preview scaled to the screen. Everything is inside a max-width query and disabled again for print, so desktop and PDFs are untouched
- **Two bios per Havoc player, written by you** — a long **media bio** used on the Game Packet pages and a short **broadcast bio** used on the lineup chart & game sheet; opponent players carry just a broadcast bio. Nothing is auto-written. Captains are marked C / A in the player editor and their letter shows everywhere names print
- **Meet the Hockey Operations Team** — head coach, assistant coach, GM and equipment manager (names + bios, user-filled on the Roster tab) print as their own Game Packet page
- **Elite Prospects widgets, where the data belongs** — career cards, team rosters and lineup decks on Rosters; an optional "EP view" of standings, leaders and schedule beside our own tables on Live Data; coaching-staff histories in League Reference. League slug, season and EP team id live under Settings → Advanced
- **Elite Prospects profile links** — a weekly GitHub Action (`.github/workflows/ep-data.yml`) matches every SPHL player to Elite Prospects via the official EP API (name + date-of-birth matching, cached forever, hand-fixable via `data/ep-overrides.json`) and commits `data/ep-players.json`; every roster name links to the player's EP page (EP search when unmatched). One-time setup in `data/README.md`
- **Broadcast folder call sheets** — one team, one page, everything at a glance: a header bar in the club's own colours carrying the team, record and standing, then the head coach's tenure and career record and the assistants (read from the roster feed's staff records and the League Reference file). Below it, compact player cards — number badge, LAST, FIRST with the letter, vitals, season stats, SPHL career totals, and two written blocks (season/career notes from the club's broadcast notes, personal notes from the junior summary and birth details) — three across for forwards, two for defence and goalies, each group edged in its own colour. A sidebar carries IR, ECHL call-ups, scratches, a bold suspension callout and write-in space for lines and notes. The whole roster plus the sidebar lands on one letter page; a sheet that stops fitting shrinks a point rather than spilling, and says so
- **Team colours** — every club's primary, secondary, accent and goalie shades with the text colour that reads on the primary, editable per team in League Reference and applied wherever that club prints. A red • marks a shade still to check against the club's own marks. The opponent's folder pages print in the opponent's colours; that is the point of separate folders
- **Folder views, not blind printing** — the four folder pages are view toggles with the current one highlighted; **Print this page** and **Print all four** are separate actions. The per-section size and weight controls keep working on whichever page is showing
- **Layout editor for the folder sheets** — turn on **Edit layout** and every text element is editable in place, every card gets a handle (size ±1 pt, bold, move earlier or later, hide, reset), the forwards, defence and goalie grids switch between 1 and 4 across, the sidebar width and block spacing step up and down, and cards drag to reorder within their group. A live fit line reads "Fits on 1 page ✓" or names the sheet and how far it overflows. Choices save per team and reapply automatically the next time that opponent comes up; **Reset this page** and **Settings → Reset all layout** put them back. It is flow-based by design — there is nothing here that can produce a sheet that won't print
- **Career stats & milestone tracker** — Rosters → Career & Milestones, driven by one committed file, `data/havoc_players.json`. The file's structure is the in-season workflow: `seasons[]` is frozen career history through 2025-26, `baseline_pro` / `baseline_havoc` are the pre-computed career totals entering 2026-27, and `current_season` is the live counter block — the only thing edited on game nights (a 30-second JSON edit, no API needed). The site displays career = baseline + current, both boards and both totals rows, and milestone flags run off those live sums; a 2026-27 row appears on the career page the moment its counters move, tagged live. After the season, fold `current_season` into `seasons[]`, recompute the baselines and zero the counters. Two boards matching the milestones sheet: **Overall Pro Career** (pro leagues only — SPHL, ECHL, FPHL, AHL, NHL and European pro, never NCAA or juniors) and **Milestones w/ Havoc** (Huntsville games only), regular season only. Skaters track GP / G / A / PTS / PIM, goalies GP / SVS / W / SO, every column sortable. Upcoming milestones flag by the sheet's windows — 100s of GP within 25, 50s of G/A within 10, 50s of PTS within 15, goalie 50s of W within 10 — tiered soon (≤5) / upcoming (≤15) / this season, and the urgent ones print as full-size call lines: "Alger is 4 games from 100 as a Havoc". A `null` in the data renders as "—", never zero and never invented; totals from Jacob's tracker (where season rows are incomplete) are marked **tracker** and win until the API refresh completes the rows. Every player also gets a career page — juniors → college → pro with playoff lines, PRO TOTALS and HAVOC TOTALS, and the research file's caveats as a footnote. Below the boards, a **franchise record watch** checks the club book (League Reference → Franchise records — edit it there and the watch follows) against live Havoc careers and the 2026-27 counters: career games, goals, assists, points and PIM, goalie wins and shutouts, and the single-season marks, each with the record holder named. A player inside the window gets a countdown line; a player already ahead of the book gets an amber "verify the record before air" — the flag that caught the stale shutouts record on day one, since confirmed by the club: the corrected book (the data file's `league_reference` block, which the seeded card now matches) lists the career record as **8 — Brian Wilson**, an active holder. When the book's holder *is* the live player, the watch goes green instead of amber: "Wilson holds the franchise shutouts record — 8 as a Havoc, and every shutout extends it" (and if his live count moves past the card, it says to update it). The corrected book also adds career goalie games (167) and saves (4,988 — both Carmichael) and the single-season goalie records — wins (26, Robinson/Carmichael) and shutouts (4, shared by Milosek, McWhinney and Wilson) — all watched with their own windows
- **Franchise race** — a third board, **All-Time Havoc**, renders the club's all-time scoring list (`franchise_records.career_leaders_points`, 52 skaters through 2025-26) in full: rank, player, GP / G / A / PTS / P-GP / PIM and years, ties sharing a rank (T-42, T-51). Current roster players join by name — "Giovanni Procopio" finds Gio — get a **ROSTER** chip, ride their live career (baseline + the game-night counters) and the list re-ranks itself as they score, a green ▲ showing spots climbed; a two-point night moves a man up the board before the Zamboni is done. On the Havoc milestone board each roster player carries a **Next Pass** badge — "passes Bushey in 4 PTS" — in the same soon (≤5) / upcoming (≤15) tiers, and the alert banners extend to the race: a pass within 3 points or the all-time top 15 within 10 prints full size. Day one that reads: Fries passes Scott Trask in 2 points, and Alger is 5 points from the top 15. The goalie side is its own chase: the club's all-time goaltender list (47 names, ranked by GP) renders below the skaters, re-sortable by GP, W, SO, SVS, SV% or GAA — the rate columns qualify at 25 Havoc games, and the table says how many sit under the line. Wilson (#5) and Proctor (#40) carry ROSTER chips; GP, wins, shutouts and saves run live off the game-night counters (GAA and SV% stay as of 2025-26, since the counters don't track goals-against or minutes), with the same climb arrows on every sort. Goalies get a wins-chase badge — day one: "Wilson passes McWhinney in 2 W" — and goalie banner lines fire on a pass within 3 wins or games (25 saves), gated to passes into a column's top 10 so a two-win rookie passing the bottom of the list doesn't drown the board. Day one that reads: Wilson passes Dan McWhinney for 3rd on the all-time wins list in 2 wins
- **Every stats table sorts** — one shared utility across the whole Rosters tab: the roster reference table (defaulting to jersey order), both milestone boards, the all-time skater and goalie lists, the career page season tables and the player modal's club stat tables. Click any column head — first click puts leaders on top for stat columns, A→Z for names, seasons and ranks, and GAA starts low-is-good; a second click reverses, ▲/▼ marks the active column, and headers read as clickable. A "—" always sinks to the bottom in either direction because a missing number is not a zero. Sorting moves the rendered rows themselves, so badges, ROSTER chips, row highlights and info popovers travel with their row; on career pages the JUNIORS / COLLEGE / PRO group headers and totals rows hold position and each group sorts within itself. Every table keeps its own last sort when you switch tabs. On the goalie chase, rate sorts keep the 25-GP qualifying line with a show-all toggle
- **Staff** — the coaching side of the franchise book, from `franchise_history.coaching_milestones`. Tenure chips for the broadcast open (Stefan — 4th season as HC · 18th in org; Detulleo — 12th as GM · 17th in org; Piacentini — 4th on staff · 10th in org, full history on hover), then the all-time head-coach table by career Havoc wins: Detulleo 312 with back-to-back Cups, Gibson 113, Stefan third. Stefan's row is live off the team record counters (`current_season.team_w/l/otl/gp` — edited on game nights right beside the player counters), with the same climb arrows. His 2025-26 (32-20-5-1), missing from the media guide table, is completed from the verified League Reference year-by-year, so he enters 2026-27 at 98 wins over 170 games — and the day-one banner reads **"Stefan is 2 wins from 100 as Havoc head coach"**, with the Gibson chase (passes him for 2nd in 16) and 200 games coached (30 away) on the chase strip
- **EP API refresh, off the browser** — GitHub Pages is static, so the EliteProspects key never appears in client code: the site only reads the committed JSON. `node scripts/update_stats.mjs` (key from `.env` or the `EP_API_KEY` secret) resolves and caches each player's EP id, pulls season-by-season stats, fills gaps without ever overwriting hand-curated values, maps EP league names explicitly (unknown = non-pro + a warning), and prints a diff for review before commit. A weekly in-season Action (`.github/workflows/ep-refresh.yml`) does the same and **opens a PR — never pushes to main** — so bad API data can't silently reach the broadcast. One refresh ≈ 17 calls against the 1,000/month plan
- **Broadcast call log** — career game tracking for 2025-26 + 2026-27, importable from the call-log app
- **Post-game copy desk** — a formatter, not a generator: you write each section (headline, lede, body, quotes, notes), it assembles the finished report in one fixed house style with a one-click Copy; a Game Center paste can auto-fill the score/date/venue facts
- **Learn the Roster** — quiz modes for play-by-play memorization

## Not indexed
`robots.txt` disallows all crawlers and every page carries `<meta name="robots" content="noindex, nofollow">`. That keeps the hub out of search results — it does **not** make it private. The repository is public and the URL is reachable by anyone who has it, which is why unannounced club material stays in the browser and out of this repo.

## Important: where your data lives
All data (rosters, results, call log, keys) is saved in the **browser's localStorage — not in this file**. That means:
- Safe to share/publish this file — it contains no personal data or keys
- **Moving between computers/URLs = data does NOT follow.** Use **Settings → Export** on the old copy and Import on the new one
- Back up with Settings → Export regularly. localStorage can be wiped by clearing browser data.
- A rolling **auto-backup** (everything except logos) is also kept in the browser — Settings → Restore auto-backup brings it back if something gets overwritten.

## Run it
Open `index.html` in a browser. That's the whole install.
