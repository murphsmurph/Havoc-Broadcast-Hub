# Havoc Game Notes Hub

> **[`HAVOC_HUB_MASTER_DOCUMENT.md`](HAVOC_HUB_MASTER_DOCUMENT.md) is the controlling document for all work in this repo. Where any other file or instruction disagrees with it, it wins.**

A single-file broadcast & media toolkit for the Huntsville Havoc (SPHL). No build, no server — one HTML file that runs in any browser.

## Operating rhythm (P0 complete — master document Part 5)
- **Nightly:** Actions refresh the daily report + every SPHL roster automatically, under the precedence rules (the roster commit is gated by the roster-precedence test; a daily report older than your live sync is held, never applied over it).
- **Game week:** prose is authored in Claude sessions and committed as JSON (`data/bios.json`, `data/matchups.json`); the Hub renders it verbatim.
- **Game night:** bump `current_season` player counters + the team record (~30 seconds, in `data/havoc_players.json`), fill the lines, run one Game Day Refresh, call the game from the **Game Day** tab.
- **Weekly in-season:** the EP refresh Action opens a PR (~17 API calls of the 1,000/month plan); review the diff, merge.
- **Season end:** rollover — fold `current_season` into `seasons[]`, recompute baselines, zero counters, **update the test anchors** in `tests/anchor_reconstruction.mjs`.

## What's inside
- **Game packet generator** — pro media-notes standard: cover (news w/ auto-draft, standings, 4-column leaders, media contact), Meet the Team, Hockey Operations, Elite Prospects career-stat pages, scouting report (series history + league-ranked Match Up), quick facts, season splits + "last time it happened", game-by-game log, roster + pronunciation guide, franchise records, blank scoring worksheets, and the dense game sheet — with a section picker and Full/Booth presets. Derived pages compute from the per-game log (auto-filled from results + attendance; shots/PP/fights hand-entered on the Schedule tab)
- **Game sheet, lineup chart & line card** — printable, per-team colors, all 12 team logos embedded
- **Print Center** — one sticky toolbar (sub-view · page count · Refresh · Clear hand overrides · Print/Save PDF · Print everything for tonight), and a per-section **A− / pt / A+ / B / reset** control that moves the printed body size exactly 1 pt per click, bolds a section's body text, saves with your layout, and warns when a section stops fitting instead of clipping silently. Any page that would spill in the PDF is outlined in the preview and labelled with what's wrong — taller than one sheet, or running past the right edge — with a **reduce this section by 1 pt** button on the page itself; **Fit every page** steps every offender down until the whole document fits, and reports what it changed
- **The packet lays itself out** — player entries and every other block flow onto as few sheets as they fit on, two or three to a page, and a block never splits across a break: it moves whole. One printed `.page` is exactly one sheet, so the PDF can never paginate differently from the preview. A section that is within 10% of fitting on one fewer page drops a point automatically (floor 7 pt) and says so. Stat rows the club could not source collapse into a single "stat line not publicly available" note instead of a full-height row each, and league names print abbreviated. On the same content this took the full packet from 38 preview / 40 printed pages to 27 and 27
- **Overflow warning** — alongside the page count, any page that overflows is outlined in red with a one-click fix on the page itself
- **Two presets** — Full and Booth, each a remembered set of packet sections
- **2026-27 schedule** — official 60-game slate + preseason, promo nights, results entry, season calendar (home red / away gray)
- **Standings & league reference** — 2026-27 rule changes, schedule matrix, all-time Havoc leaders, head-to-head, plus a seeded **2026 season review & New Teams 2026-27** card: the President's Cup final and full playoff bracket, the 12-team table (2025-26 records, finishes, 2026-27 head coaches) and FPHL franchise files for Athens and Pee Dee. A red • marks anything still unverified; content changes go through the committed data files. The venue reference covers all 12 buildings
- **Franchise files** — a deep, researched file on each of the 12 clubs: founding and arena, season-by-season table, all-time record, championships and Finals, all-time leaders, records and awards, attendance, retired numbers and the current coach, plus a **running "Havoc all-time vs. them"** line that starts from the published baseline and accumulates from your own game log, and a per-team storylines box pre-filled with cross-team notes. Sourcing caveats travel with the text (a red • flags computed, single-sourced or disputed numbers), content changes go through the committed data files, and nothing here is ever overwritten by a sync
- **Live scorebar** — league-wide SPHL scores (recent finals, tonight, week ahead) that update every minute while games are on, every 15 minutes otherwise, and pause while the tab is hidden; standings and stats also quietly refresh hourly. It always resolves: connected with a timestamp, or failed with the reason, a Retry and the last cached scores. A compact tonight-only strip also sits on This Game
- **One explicit season** — a season picker sits at the top of Live Data, listing the league's real season names newest-first, and the active season prints beside the Refresh button in large type. The default is the highest season id that is neither a playoff nor a career aggregate — sorted numerically, never by array position and never from a "current" flag, which is what once had a Game Day Refresh pulling 2015 Playoffs. That one value drives every call: standings, skater and goalie stats, schedule, every team roster, career stats, headshots, the scoreboard and Elite Prospects linking, with each step in the run report naming the season it used. A season whose end date is more than 18 months past refuses to sync and says so
- **Preseason fallback, always labelled** — 2026-27 exists but the league hasn't published rosters or stats for it, so when a feed comes back empty the hub re-runs the same pull against the previous regular season and marks it: "2025-26 (last season) — 2026-27 not yet published". The label shows on screen and on every printed page. Nothing from another season is ever shown as if it were current, and the fallback stops firing by itself the day the league publishes
- **One Game Day Refresh** — a single button runs everything tonight needs in order (connect, standings, stats, schedule, rosters, career stats + headshots, EP links, scoreboard) with a step list showing each result; individual pulls live behind an Advanced disclosure, and the connection check runs itself and reports as a chip
- **Freshness everywhere** — every feed carries its own "Updated 6:42 PM", and every printed page ends with a single stacked footer block — the freshness line, then the rule and the footer row, each on its own row so they cannot print on top of one another, with the flow above reserving its height — reading "Data: SPHL feed <date/time> · daily report <date> · printed <date/time>", plus "(includes manual edits)" when overrides are live
- **Booth display** — dark mode (following the OS by default) and a booth type scale, neither of which touches printed output
- **Keyless daily-report baseline** — a nightly GitHub Action (`.github/workflows/sphl-daily.yml`) fetches the league's public daily report (no key needed), parses it with `js/daily-report-parser.js`, and commits `data/sphl-daily.json`; the site loads it as its data floor with a source badge. The same parser powers manual import: open the report, save the page, upload the .html (or paste it) — per-section parse summary included, works offline. Live feed data overlays this when available
- **Live SPHL data** — one-tap sync from the league's HockeyTech feed (standings, all player/goalie stats, full schedule + auto-filled final scores, and every team's roster). Works both hosted (GitHub Pages etc.) and opened as a local file; the feed key is auto-detected, and everything is saved to this browser after each sync. The latest daily report can also always be pasted in by hand as a manual fallback — same parsed data either way
- **Player photos from the roster feed** — the league's roster response carries `player_image` and the hub uses it verbatim, keyed by the roster `id`. It tries the one larger size that exists (240x240, probe-confirmed; 240x320 and 360x480 return 404) and falls back to the feed's own 120x160. The 2026-27 Havoc roster is coaches-only so far, so every sync also backfills photos for returning players from 2025-26 by name; new signings stay text-only and pick up a photo automatically once the league publishes them. The service worker caches the CDN so packets still build with photos offline
- **The league feed owns the vitals** — hometown, height, weight, date of birth, age, position, jersey number, headshot and pronunciation come from the SPHL roster feed and overwrite whatever the club's bios file said, silently, on every sync. `homeplace` is the hometown (the feed's `hometown` field comes back empty); a birthplace prints separately only when it differs. A value you typed into the player editor yourself is the one thing the feed will not overwrite. Nothing is invented: the feed carries no handedness, no draft status and no phonetic spellings today, so those come from the committed data files, and a player the feed leaves without a pronunciation prints as “— ask him —” in the pronunciation guide. A column that reads identically for every player on the roster — the rookie flag does — is treated as formatting, not fact, and ignored. 2026-27 has no players published yet, so returning players fill in from 2025-26 and re-sync when the league posts them
- **Mobile** — `mobile.css` (loaded after the inline styles) gives phones a compact header, a scrolling tab strip with an edge fade, one-row sub-view pills, a 2-up action grid, thumb-sized controls, 16px inputs so iOS never zooms on focus, wide tables that scroll inside their own box with a frozen first column, and a print preview scaled to the screen. Everything is inside a max-width query and disabled again for print, so desktop and PDFs are untouched
- **The authoring loop (cleanup Phase 5)** — everything written lives in committed `data/bios.json`, authored on the Mac and never edited by the site. The hub renders it everywhere prose prints: **Meet the Team** (joined-the-Havoc line, season recap, career highlights, footnotes — the bio pages' structure), the **broadcast call sheets** and folder lineup notes (`broadcast_bio`), the **lineup chart & dense game sheet** (`broadcast_bio`), the **pronunciation guide** (feed phonetic first, then the authored `pronunciation`), and the **Hockey Operations page** (empty roles fill from the staff bios). Precedence everywhere: the committed file wins when it has content, the browser's hand-typed field is the fallback, and `embargoed: true` withholds a player's prose from every surface. The hub roster itself **baselines from the committed spine** (`data/havoc_players.json`): a fresh browser shows the signed 17-man roster with numbers, positions and vitals before the league publishes 2026-27 — the roster file, live feed and hand edits overlay in rising authority. Opponent players still carry a hand-typed broadcast bio; captains show their letter everywhere names print
- **Meet the Hockey Operations Team** — head coach, assistant coach, GM and equipment manager (names + bios, user-filled on the Roster tab) print as their own Game Packet page
- **Elite Prospects profile links** — a weekly GitHub Action (`.github/workflows/ep-data.yml`) matches every SPHL player to Elite Prospects via the official EP API (name + date-of-birth matching, cached forever, hand-fixable via `data/ep-overrides.json`) and commits `data/ep-players.json`; every roster name links to the player's EP page (EP search when unmatched). One-time setup in `data/README.md`
- **Broadcast folder call sheets** — one team, one page, everything at a glance: a header bar in the club's own colours carrying the team, record and standing, then the head coach's tenure and career record and the assistants (read from the roster feed's staff records and the League Reference file). Below it, compact player cards — number badge, LAST, FIRST with the letter, vitals, season stats, SPHL career totals, and two written blocks (season/career notes from the club's broadcast notes, personal notes from the junior summary and birth details) — three across for forwards, two for defence and goalies, each group edged in its own colour. A sidebar carries IR, ECHL call-ups, scratches, a bold suspension callout and write-in space for lines and notes. The whole roster plus the sidebar lands on one letter page; a sheet that stops fitting shrinks a point rather than spilling, and says so
- **Team colours** — every club's primary, secondary, accent and goalie shades with the text colour that reads on the primary, editable per team in League Reference and applied wherever that club prints. A red • marks a shade still to check against the club's own marks. The opponent's folder pages print in the opponent's colours; that is the point of separate folders
- **Folder views, not blind printing** — the four folder pages are view toggles with the current one highlighted; **Print this page** and **Print all four** are separate actions. The per-section size and weight controls keep working on whichever page is showing
- **Career stats & milestone tracker** — Rosters → Career & Milestones, driven by one committed file, `data/havoc_players.json`. The file's structure is the in-season workflow: `seasons[]` is frozen career history through 2025-26, `baseline_pro` / `baseline_havoc` are the pre-computed career totals entering 2026-27, and `current_season` is the live counter block — the only thing edited on game nights (a 30-second JSON edit, no API needed). The site displays career = baseline + current, both boards and both totals rows, and milestone flags run off those live sums; a 2026-27 row appears on the career page the moment its counters move, tagged live. After the season, fold `current_season` into `seasons[]`, recompute the baselines and zero the counters. Two boards matching the milestones sheet: **Overall Pro Career** (pro leagues only — SPHL, ECHL, FPHL, AHL, NHL and European pro, never NCAA or juniors) and **Milestones w/ Havoc** (Huntsville games only), regular season only. Skaters track GP / G / A / PTS / PIM, goalies GP / SVS / W / SO, every column sortable. Upcoming milestones flag by the sheet's windows — 100s of GP within 25, 50s of G/A within 10, 50s of PTS within 15, goalie 50s of W within 10 — tiered soon (≤5) / upcoming (≤15) / this season, and the urgent ones print as full-size call lines: "Alger is 4 games from 100 as a Havoc". A `null` in the data renders as "—", never zero and never invented; totals from Jacob's tracker (where season rows are incomplete) are marked **tracker** and win until the API refresh completes the rows. Every player also gets a career page — juniors → college → pro with playoff lines, PRO TOTALS and HAVOC TOTALS, and the research file's caveats as a footnote. Below the boards, a **franchise record watch** checks the club book (the committed record book in the data file — update it there and the watch follows) against live Havoc careers and the 2026-27 counters: career games, goals, assists, points and PIM, goalie wins and shutouts, and the single-season marks, each with the record holder named. A player inside the window gets a countdown line; a player already ahead of the book gets an amber "verify the record before air" — the flag that caught the stale shutouts record on day one, since confirmed by the club: the corrected book (the data file's `league_reference` block, which the seeded card now matches) lists the career record as **8 — Brian Wilson**, an active holder. When the book's holder *is* the live player, the watch goes green instead of amber: "Wilson holds the franchise shutouts record — 8 as a Havoc, and every shutout extends it" (and if his live count moves past the card, it says to update it). The corrected book also adds career goalie games (167) and saves (4,988 — both Carmichael) and the single-season goalie records — wins (26, Robinson/Carmichael) and shutouts (4, shared by Milosek, McWhinney and Wilson) — all watched with their own windows
- **League Reference renders from the data file** — the President's Cup counts (with each club's note and the defunct-franchise line) and the whole franchise record book come from `league_reference` in `data/havoc_players.json` through one accessor, with the seeded copy only as a fallback until the file loads. Records with a club note — Wilson's active shutout record, the Wilson chases on goalie wins/games/saves — print it as a small chaser line under the row. The record watch, the Game Notes minis and the packet records page all read through the same accessor, so a correction committed to the data file follows everywhere
- **Dynamic rank column** — the # on the all-time skater, goalie and coach lists is never stored data: it re-ranks 1..N for whatever stat the table is sorted by, ties on the sorted value sharing a rank (T-45, T-45, 47), rows with — in that column ranking as — at the bottom, and name/season sorts blanking the ranks entirely. The official list rank survives as a small gray second line whenever it differs — sort the all-time list by goals and the top row reads "1" with "17" underneath — and clicking # restores the canonical list exactly
- **Franchise race** — a third board, **All-Time Havoc**, renders the club's all-time scoring list (`franchise_records.career_leaders_points`, 52 skaters through 2025-26) in full: rank, player, GP / G / A / PTS / P-GP / PIM and years, ties sharing a rank (T-42, T-51). Current roster players join by name — "Giovanni Procopio" finds Gio — get a **ROSTER** chip, ride their live career (baseline + the game-night counters) and the list re-ranks itself as they score, a green ▲ showing spots climbed; a two-point night moves a man up the board before the Zamboni is done. On the Havoc milestone board each roster player carries a **Next Pass** badge — "passes Bushey in 4 PTS" — in the same soon (≤5) / upcoming (≤15) tiers, and the alert banners extend to the race: a pass within 3 points or the all-time top 15 within 10 prints full size. Day one that reads: Fries passes Scott Trask in 2 points, and Alger is 5 points from the top 15. The goalie side is its own chase: the club's all-time goaltender list (47 names, ranked by GP) renders below the skaters, re-sortable by GP, W, SO, SVS, SV% or GAA — the rate columns qualify at 25 Havoc games, and the table says how many sit under the line. Wilson (#5) and Proctor (#40) carry ROSTER chips; GP, wins, shutouts and saves run live off the game-night counters (GAA and SV% stay as of 2025-26, since the counters don't track goals-against or minutes), with the same climb arrows on every sort. Goalies get a wins-chase badge — day one: "Wilson passes McWhinney in 2 W" — and goalie banner lines fire on a pass within 3 wins or games (25 saves), gated to passes into a column's top 10 so a two-win rookie passing the bottom of the list doesn't drown the board. Day one that reads: Wilson passes Dan McWhinney for 3rd on the all-time wins list in 2 wins
- **Every stats table sorts** — one shared utility across the whole Rosters tab: the roster reference table (defaulting to jersey order), both milestone boards, the all-time skater and goalie lists, the career page season tables and the player modal's club stat tables. Click any column head — first click puts leaders on top for stat columns, A→Z for names, seasons and ranks, and GAA starts low-is-good; a second click reverses, ▲/▼ marks the active column, and headers read as clickable. A "—" always sinks to the bottom in either direction because a missing number is not a zero. Sorting moves the rendered rows themselves, so badges, ROSTER chips, row highlights and info popovers travel with their row; on career pages the JUNIORS / COLLEGE / PRO group headers and totals rows hold position and each group sorts within itself. Every table keeps its own last sort when you switch tabs. On the goalie chase, rate sorts keep the 25-GP qualifying line with a show-all toggle

- **Bio pages — 17 players + 3 hockey-ops staff, website and packet page in one** — `player.html?p=<name or slug>` (players) and `player.html?s=<name>` (staff) generate the game-notes bio pages from the two reference templates. Everything computed comes from `data/havoc_players.json`: career tables from `seasons[]` (group headers, playoff split, totals off the baselines plus live counters), season counters ("3rd season with the Havoc · 3rd in the SPHL · 3rd as a pro"), and for staff the coaching record (per-season rows with PCT, the assistant stint, live 2026-27 team record row, totals bar) plus the playing-career line straight off the all-time list — Stefan's page carries his 379* franchise games record, the corrected **16th-in-org** tenure (7 player + 5 assistant + entering his 4th as HC, also fixed on the hub's Staff chips), and Detulleo's spans both careers. All prose lives in `data/bios.json` — authored externally, the site never edits it; a missing section renders an italic *"— bio to come —"* slot and the generator **never invents a word**. Vitals prefer the committed roster-feed file, fall back to the bio vitals block, and otherwise the item is omitted — never guessed. When `current_season` counters move, a "**2026-27 to date:**" line appears on its own, so pages stay current all season with no prose edits. `embargoed: true` in bios.json removes a player from the page, the picker and the index. `bios.html` indexes everyone, staff at the top; hub career pages link out; and the print stylesheet exports any page as exactly one letter sheet (auto-fit) — the packet page and the website page are the same page. Data caveats print as small italic footnotes from each entry's `footnotes` field (falling back to the data-spine notes). The full prose batch is loaded for all 20 pages — players carry `broadcast_bio` on-air shorthand lines and, where set, a `formal_name`/`nickname` pair (the header prints *Giovanni Procopio*; "Gio" is the on-air name; data joins keep the spine key)
- **Daily roster auto-update (cleanup Phase 2)** — the nightly Action also fetches **every SPHL team's roster** from the HockeyTech feed (`scripts/fetch-rosters.mjs`) and commits `data/sphl-rosters.json`: trimmed raw feed rows per team, the newest regular season picked by the same rule as the site's season picker, and the key resolved env → known → auto-detected from the league site. It **fails soft** — a dead key, an empty feed or a fetch that shrinks the league by more than half keeps the last good file and never blocks the keyless daily report, which remains the fallback floor. The site loads this committed file as the **roster baseline** (applied through the same ownership gate, so hand edits still win and the live browser sync is an overlay on top), shows the file's timestamp as a chip on the Rosters tab, and the bio pages read their vitals and headshots from it first
- **Trimmed for the booth (cleanup Phase 3)** — the Learn-the-Roster quiz, Post-Game copy desk, Call Log tab, EliteProspects widget embeds, embargo mode and the club-bios import / signed-sheet reconcile have been removed: authored content now lives in committed JSON (`data/bios.json`, `data/havoc_players.json`), `embargoed: true` in bios.json is the embargo control, and the 2025-26 booth history is preserved in `data/archive_2025-26_logs.json`. Phase 4 removed the per-block nudge controls, the page inspector's empty-page hints, the folder layout editor, the Compact preset and every in-place content editor — the packet, chart, folders, League Reference and record book render read-only from data, with **Print Center per-section sizing + Fit every page** as the only layout system and the game-night number tools (stat-line edits, packet/folder value corrections, game log, final scores) untouched
- **Adding a player mid-season** — the hub roster, packet and game sheet pick a new signing up **automatically** from the live SPHL feed the moment the league publishes him (use **+ Add one player** on the Rosters tab if he's signed before that — hand fields survive later syncs). Everything that renders from the committed files — milestone boards, career pages, record watch, bio pages — needs one local command: `node scripts/add_player.mjs "First Last"` (`--dry-run` to preview; `--num/--pos/...` flags when the feed hasn't published him). It pulls vitals from `data/sphl-rosters.json`, scaffolds his frozen career history from EliteProspects when the `.env` key is present and the name match is unambiguous (storing `ep_id` so the weekly sync never searches for him again), computes the baselines, zeroes `current_season`, and adds a `data/bios.json` stub whose empty prose renders "— bio to come —" until it's written. Additive only — it aborts rather than touch an existing entry. Review the git diff, commit/PR, then write the prose into bios.json whenever it's ready. Departures: mark the player inactive in the hub; his spine entry stays — it's career history
- **In-season EP sync, three layers** — GitHub Pages is static, so the EliteProspects key never appears in client code (`.env` + the `EP_API_KEY` repo secret only). **Layer 1**: `node scripts/update_stats.mjs` pulls each player's 2026-27 Huntsville line and updates **only** `current_season` — the frozen `seasons[]`, baselines and bio prose are behind a hard guard — printing every change as before → after so the season's first run can be checked for player-mapping mistakes. Counters **never go down**: a lagging EP value prints a warning instead of clobbering a fresher game-night bump. `--backfill` keeps the off-season mode that completes historical gaps without ever overwriting hand-curated values. **Layer 2**: the Action (`.github/workflows/ep-refresh.yml`) runs Fri/Sat/Sun 11:00 UTC in season (plus manual dispatch) and **opens a PR — never pushes to main**. **Layer 3**: game-night precision is a 20-second `current_season` edit; the next API run reconciles anything missed. One run ≈ 17 calls against the 1,000/month plan

## Not indexed
`robots.txt` disallows all crawlers and every page carries `<meta name="robots" content="noindex, nofollow">`. That keeps the hub out of search results — it does **not** make it private. The repository is public and the URL is reachable by anyone who has it, which is why unannounced club material stays in the browser and out of this repo.

## Important: where your data lives
All data (rosters, results, keys) is saved in the **browser's localStorage — not in this file**. That means:
- Safe to share/publish this file — it contains no personal data or keys
- **Moving between computers/URLs = data does NOT follow.** Use **Settings → Export** on the old copy and Import on the new one
- Back up with Settings → Export regularly. localStorage can be wiped by clearing browser data.
- A rolling **auto-backup** (everything except logos) is also kept in the browser — Settings → Restore auto-backup brings it back if something gets overwritten.

## Run it
Open `index.html` in a browser. That's the whole install.
